## 2. Scoring Methodologies

The most striking difference between systems is their dimensional scoring approach.

### Sound: Additive Scoring (ChirpIQX)

```
Breakout Score = (Recent x 40%) + (Projected x 30%) + (Opportunity x 20%) - (Risk x 10%)
```

**Why Additive:**
- Sound waves combine through **superposition** (linear addition)
- Multiple signals coexist without canceling
- Partial scores are meaningful (high recent + low projected = moderate signal)

**Example:**
```
Player A: Recent=9, Projected=3, Opportunity=8, Risk=2
Score = (9x0.4) + (3x0.3) + (8x0.2) - (2x0.1) = 3.6 + 0.9 + 1.6 - 0.2 = 5.9
--> MONITOR (mixed signals)
```

### Space: Multiplicative Scoring (PerchIQX)

```
ICE Score = (Insight x Context x Execution) / 100
```

**Why Multiplicative:**
- Spatial position requires **all three coordinates** (X, Y, Z)
- Missing any dimension = collapse to lower-dimensional space
- Zero in any factor collapses priority entirely

**Example:**
```
Finding A: Insight=9, Context=3, Execution=9
ICE = (9 x 3 x 9) / 100 = 2.43 --> LOW (context dimension missing)

Finding B: Insight=7, Context=7, Execution=7
ICE = (7 x 7 x 7) / 100 = 3.43 --> MEDIUM (all dimensions present)
```

**Key Insight:** Finding A has higher individual scores but **lower priority** because the context dimension is weak. This is **spatial reasoning** — you need all three axes.

### Time: Exponential Decay (WakeIQX)

```
Relevance = BaseRelevance x TemporalDecay x AccessBoost
TemporalDecay = e^(-age / half-life)
```

**Why Exponential:**
- Context relevance **decays over time** (exponential function)
- Recent context has **higher weight** (recency bias)
- Access patterns **boost relevance** (LRU principle)

**Example:**
```
Context Item A: Created 1 day ago, last accessed 1 hour ago
Decay = e^(-1/24) = 0.96   AccessBoost = 0.92
Relevance = 1.0 x 0.96 x (1 + 0.92x0.3) = 1.23 --> HIGH

Context Item B: Created 30 days ago, never accessed
Decay = e^(-30/24) = 0.29   AccessBoost = 0
Relevance = 1.0 x 0.29 x 1.0 = 0.29 --> LOW
```

**Key Insight:** WakeIQX uses **continuous time functions** (exponentials), not discrete scores. This reflects temporal physics.

## 3. Mathematical Model Comparison

| Property | Sound (Additive) | Space (Multiplicative) | Time (Exponential) |
|----------|-----------------|----------------------|-------------------|
| **Formula type** | Linear combination | Product | Exponential decay |
| **Zero behavior** | Partial score remains | Total collapse | Never reaches zero |
| **Partial information** | Meaningful | Meaningless | Gradually degrading |
| **Physics analog** | Superposition | Cartesian coordinates | Radioactive decay |
| **Key parameter** | Weights (0.4/0.3/0.2/0.1) | Factor count (3) | Half-life (tau) |
| **Failure mode** | Over-averaging | Over-penalizing gaps | Premature forgetting |

### Why Different Models Are Required

Each mathematical model is **uniquely suited** to its dimension:

- **Additive** works for Sound because urgency signals **combine** — hearing two alarms is louder, not silent
- **Multiplicative** works for Space because structure requires **completeness** — a building with no foundation has zero structural integrity regardless of how good the roof is
- **Exponential** works for Time because memory **fades continuously** — there's no discrete moment when a context becomes irrelevant

Attempting to use the wrong model creates dimensional mismatches:
- Multiplicative scoring for Sound would mean any zero factor kills the entire urgency signal (wrong — a weak projected score shouldn't eliminate strong recent performance)
- Additive scoring for Space would allow a finding with zero context to still have moderate priority (wrong — no context means the finding isn't actionable)
- Discrete scoring for Time would create artificial cliff edges in memory relevance (wrong — relevance degrades smoothly)
